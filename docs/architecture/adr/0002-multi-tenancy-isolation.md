# ADR 0002: Multi-Tenancy & Data Isolation

## Status
Accepted

## Context
Платформа Dental SaaS обслуживает независимые стоматологические клиники и сети клиник (Tenants). Утечка данных между клиниками (Cross-Tenant Data Leakage), особенно медицинских записей и финансовой информации, является критическим инцидентом безопасности.

## Decision
1. **Иерархия изоляции**: `Tenant` -> `Organization` -> `Branch` -> `Department` / `Room` / `Chair`.
2. **Колонки идентификации**: Каждая бизнес-таблица обязана содержать колонку `tenant_id UUID NOT NULL`. Таблицы локаций содержат `branch_id UUID`.
3. **Безопасный контекст**: Клиентский фронтенд никогда не передает `tenant_id` в теле мутаций или query-параметрах как источник правды. Идентификатор тенанта извлекается исключительно из валидированного токена авторизации (JWT / сессия).
4. **Prisma Extensions / Application Middleware**: Запросы к данным автоматически фильтруются по `tenantId`.
5. **Тестирование изоляции**: В CI/CD включается обязательный тест `tenant-isolation.spec.ts`, проверяющий невозможность доступа одного тенанта к данным другого.

## Consequences
- Исключается случайный доступ сотрудников одной клиники к пациентам или выручке другой клиники.
- Подготовлена база для последующего включения PostgreSQL Row-Level Security (RLS).
