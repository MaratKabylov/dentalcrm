# ADR 0001: Modular Monolith Architecture

## Status
Accepted

## Context
Система Dental SaaS создается как высоконадежная облачная платформа для управления стоматологическими клиниками в Казахстане. На начальном этапе выбор микросервисной архитектуры привел бы к преждевременным накладным расходам на распределенные транзакции (особенно критичные в медицинских протоколах и финансовом ledger), усложнил бы DevOps и замедлил темп разработки.

## Decision
Принято решение реализовать систему как **модульный монолит (Modular Monolith)**:
1. Единый backend-сервер (`apps/api`) с изолированными доменными модулями (Platform, Organizations, Identity, Employees, Patients, Scheduling, Clinical, Finance, Inventory и т.д.).
2. Домены не обращаются к чужим базам данных напрямую и не делают сквозных мутаций в обход доменных сервисов.
3. Межмодульное взаимодействие организовано через сервисные контракты и Transactional Outbox события.
4. Структура монорепозитория разделяет API, фоновые воркеры (`apps/worker`), web-интерфейс (`apps/web`) и общие библиотеки (`packages/contracts`).

## Consequences
- Быстрый цикл разработки и простое локальное тестирование.
- Надежные ACID-транзакции в рамках одного домена (например, прием оплаты + запись в Ledger + Outbox-событие).
- Любой модуль при необходимости высокой масштабируемости в будущем может быть выделен в отдельный микросервис без изменения внешних контрактов.
