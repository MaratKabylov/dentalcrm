# Phase 11 — Advanced Analytics

Phase 11 exposes read-only operational analytics over the immutable clinical, finance, compensation, laboratory, CRM, and inventory records created in earlier phases. It does not persist report totals or maintain a second financial source of truth.

Every request requires an organization, an inclusive date range of at most 366 days, and a currency. An optional branch narrows sources that have branch ownership. Organization-wide requests require organization-level membership; a branch-scoped member must request an explicitly permitted branch.

## Metric definitions

### Treatment acceptance

The cohort contains each treatment plan whose first presentation occurred in the requested range. The denominator is the value and count of presented items. The numerator uses immutable `treatment_plan_acceptances` recorded before the end of the range. Results include overall and per-service count- and value-based acceptance rates in basis points.

For a branch filter, only plans linked to an opportunity in that branch are included. Plans without a branch-bearing opportunity remain visible only in organization-wide analytics.

### Chair economics

Chair metrics use appointments that overlap the requested range. Cancelled, no-show, and rescheduled appointments are excluded from booked minutes. Completed minutes count completed appointments only. Revenue is posted charge revenue whose encounter points to the appointment. The report returns appointment counts, no-shows, booked and completed minutes, revenue, completion rate, and revenue per completed chair-hour.

The current domain has no independent chair-opening-hours calendar, so the endpoint intentionally does not label booked time as utilization. That ratio can be added once explicit chair capacity is modeled.

### Contribution margin

Contribution margin is calculated per service:

`posted charge items - confirmed material cost - laboratory item cost - approved procedure payroll accruals`

Material cost uses the immutable stock movements generated by confirmed procedure consumption and the purchase-price snapshot on each batch. Laboratory costs come from lab-case items linked to a procedure. Labor includes only approved payroll accruals with a procedure source. The endpoint returns each cost component, total variable cost, contribution margin, and margin basis points.

### Marketing attribution and ROAS

Source attribution is first-touch: the earliest converted lead for a patient owns posted revenue in the selected period. It reports lead volume, conversions, conversion rate, and attributed revenue by lead source.

Campaign ROAS uses explicit immutable patient attribution and append-only campaign spend:

`ROAS = attributed posted revenue / campaign spend`

Only revenue posted after attribution is counted. The API returns both a decimal multiple and basis points. A campaign with no spend has a null ROAS instead of an infinite value.

### Inventory analytics

On-hand quantity and value are derived from stock movements up to the report end. Period consumption and write-off cost use their posted document types. Days of stock equals ending on-hand divided by average daily consumption for the inclusive range. Products with no consumption have a null days-of-stock value. The below-minimum flag compares derived on-hand quantity with the product minimum.

## Marketing write model

- `marketing_campaigns` stores organization-scoped campaign metadata and optional CRM source/channel relationships.
- `marketing_spend_entries` is append-only and idempotent per organization.
- `marketing_attributions` is immutable and permits one attribution per patient and model in an organization.
- All mutations write audit and transactional outbox records.

## HTTP surface

Reports:

- `GET /api/v1/analytics/treatment-acceptance`
- `GET /api/v1/analytics/chair-economics`
- `GET /api/v1/analytics/contribution-margin`
- `GET /api/v1/analytics/marketing-attribution`
- `GET /api/v1/analytics/roas`
- `GET /api/v1/analytics/inventory`

Report query parameters are `organizationId`, optional `branchId`, `from`, `to`, and optional `currency` (default `KZT`).

Marketing inputs:

- `POST /api/v1/analytics/marketing/campaigns`
- `POST /api/v1/analytics/marketing/campaigns/:id/spend`
- `POST /api/v1/analytics/marketing/attributions`

Reporting requires `analytics.read` or the more sensitive `analytics.financial.read`. Campaign, spend, and attribution writes require `analytics.marketing.manage`.

## Verification

`advanced-analytics.integration.test.ts` verifies event-based treatment acceptance, chair production, contribution margin, first-touch attribution, campaign ROAS, and inventory valuation against a real PostgreSQL database.
