# Филиалы и справочники — план реализации

Статус документа: согласован 26 сентября 2026 года.

## Согласованная модель

- Пациент и медицинская история общие для всей организации.
- Приёмы, расписание, CRM, касса, финансы, склад и отчёты относятся к филиалу.
- Роль и права сотрудника общие для организации.
- Доступ к данным филиалов назначается отдельно от роли.
- Сотрудник может работать в нескольких филиалах.
- Расписание, кабинет, доступность и набор услуг сотрудника задаются по филиалам.
- Правила вознаграждения и процент оплаты общие для организации.
- Услуги бывают общими и локальными; общую услугу можно настраивать по филиалу.
- Цена бывает общей или филиальной. Изменение прайса не меняет старые документы.
- Глобальными справочниками управляют владелец и администратор, локальными — также управляющий доступного филиала.
- Используемые сущности архивируются, а не удаляются физически.

## Матрица доступа

| Область | Правило |
| --- | --- |
| Карточка пациента | Общая для организации |
| Медицинская история | Общая при наличии `clinical.read` |
| Расписание и записи | Только разрешённые филиалы |
| CRM и задачи | Только разрешённые филиалы для филиальных записей |
| Счета, платежи, кассы и долги | Только разрешённые филиалы |
| Склады и движения | Только разрешённые филиалы |
| Аналитика | Только разрешённые филиалы; агрегат «Все» строится по ним |
| Глобальные услуги и справочники | По глобальному праву |
| Локальные услуги и справочники | По праву и доступу к филиалу |

## Правила поставки

Каждый этап завершается отдельно: миграциями, серверной авторизацией, тестами и проверкой обратной совместимости. Интерфейс не считается защитой данных; окончательное решение всегда принимает БД или серверный слой.
